# v0.2 — Operational visibility and hardening

v0.2 evolves the upstream identity monitor from a validated observable component into something an operator can run continuously and inspect safely.

The release remains observation-only. It does not block upstream connections or enforce certificate/SPKI policy.

## Planned v0.2 scope

1. Read-only NGINX status endpoint backed by the existing shared-memory identity state.
2. First-class NGINX directive for the structured-history Unix socket.
3. Export and state counters so dropped events are visible.
4. Explicit peer-first-seen semantics and peer-set visibility.
5. Productionized C history collector.
6. Broader NGINX compatibility CI.
7. Expanded correctness, failure and load tests.
8. Operator/security documentation.

The implementation stays in C. No JSON library, database client, Kafka client, systemd library, Python runtime collector, or other new runtime library dependency is introduced.

## Implemented slice 1 — C collector hardening

`lab/history_collector.c` now supports configurable durability, log reopen and safer local-socket handling while remaining compatible with the v0.1 event transport.

### Sync policy

```bash
nginx-upstream-identity-history-collector \
  --sync always \
  /run/nginx/upstream-identity/history.sock \
  /var/log/nginx/upstream-identity.jsonl
```

or:

```bash
nginx-upstream-identity-history-collector \
  --sync none \
  /run/nginx/upstream-identity/history.sock \
  /var/log/nginx/upstream-identity.jsonl
```

`always` is the default and calls `fdatasync()` after every accepted event. `none` relies on normal kernel/filesystem writeback.

### SIGHUP log reopen

The collector handles `SIGHUP` by reopening the configured history path. This supports external log rotation without restarting the Unix datagram listener.

### Safer socket handling

Before binding, the collector checks an existing socket path with `lstat()`.

- no existing path: continue;
- existing Unix socket: unlink it and bind a fresh listener;
- existing regular file, directory or symlink: refuse to replace it.

After bind, the socket path is explicitly set to mode `0600`.

### Collector diagnostics

On shutdown the collector reports process-local totals:

```text
received=<n> written=<n> dropped=<n> reopens=<n>
```

## Implemented slice 2 — operational NGINX status

v0.2 now builds a second HTTP module into the same dynamic addon binary:

```text
ngx_http_upstream_identity_module
ngx_http_upstream_identity_status_module
```

NGINX supports multiple module names from one dynamic-module source set; the first name remains the output binary name.

### Read-only status endpoint

Configure the existing shared state zone first:

```nginx
http {
    upstream_identity_state_zone upstream_identity_state 1m;

    server {
        listen 127.0.0.1:8081;

        location = /upstream-identity-status {
            upstream_identity_status upstream_identity_state;
        }
    }
}
```

The status directive intentionally takes the state-zone name explicitly in this first v0.2 implementation. This avoids hidden coupling between the status module and the primary module configuration structure.

A response is a bounded JSON snapshot similar to:

```json
{
  "schema_version": 2,
  "generated_at": 1786790000,
  "counters": {
    "peers_tracked": 1,
    "events_generated": 3,
    "events_exported": 3,
    "events_dropped": 0,
    "export_errors": 0,
    "identity_changes": 2
  },
  "peers": [
    {
      "upstream": "backend_tls",
      "peer": "127.0.0.1:9443",
      "first_seen": 1786780000,
      "last_seen": 1786789994,
      "observations": 120,
      "changes": 2,
      "cert_sha256": "...",
      "spki_sha256": "..."
    }
  ]
}
```

The snapshot is generated from the shared red-black-tree state and is capped at 1 MiB in this first implementation.

Only `GET` and `HEAD` are accepted.

The endpoint is opt-in and should be protected with normal NGINX access controls because it exposes internal upstream names, peer addresses and TLS identity hashes. For example:

```nginx
location = /upstream-identity-status {
    allow 127.0.0.1;
    deny all;

    upstream_identity_status upstream_identity_state;
}
```

## Implemented slice 3 — NGINX-side operational counters

The shared state now tracks:

```text
peers_tracked
events_generated
events_exported
events_dropped
export_errors
identity_changes
```

Semantics:

- `peers_tracked` — unique `(upstream, peer)` identities currently represented in the shared state;
- `events_generated` — classified change events generated by the state machine, including `first_seen`;
- `events_exported` — structured events successfully sent to the Unix datagram socket;
- `events_dropped` — nonblocking export attempts dropped because the socket could not accept the event immediately;
- `export_errors` — other structured-export failures;
- `identity_changes` — certificate/SPKI transitions after the initial first observation.

If structured export is not configured, `NGX_DECLINED` is not counted as a dropped event or export error.

## Implemented slice 4 — first-class history socket directive

v0.1 used the NGINX core `env` directive:

```nginx
env NGX_UPSTREAM_IDENTITY_HISTORY_SOCKET=/tmp/history.sock;
```

v0.2 adds a direct HTTP-main configuration directive:

```nginx
http {
    upstream_identity_history_socket /run/nginx/upstream-identity/history.sock;
}
```

The v0.1 environment-variable mechanism remains as a compatibility fallback when the new directive is absent.

The exporter still creates one nonblocking Unix datagram socket lazily in each worker when the first change event needs to be sent.

## Compatibility

The positional v0.1 collector invocation remains valid:

```bash
nginx-upstream-identity-history-collector \
  /tmp/history.sock \
  /tmp/history.jsonl
```

It is equivalent to `--sync always`.

The structured event schema remains version 1 for exported history events in the current v0.2 branch. The status-document schema is version 2.

The explicit `peer_first_seen` event-name migration is deferred until compatibility behavior is designed and tested; existing `first_seen` history consumers should not be broken casually.

## CI coverage currently implemented

CI verifies:

- collector and sender compile as C11 with `-Wall -Wextra -Wpedantic -Werror`;
- Unix datagram transport persists a valid event;
- collector socket permissions are `0600`;
- `--sync none` works;
- `--sync always` works;
- `SIGHUP` reopens a rotated history file;
- post-rotation events are written to the new file;
- the NGINX 1.28.0 dynamic module builds with both HTTP module symbols.

Runtime status-endpoint validation and broader NGINX-version CI are the next test additions.

## Remaining v0.2 work

The next substantial work should be:

1. Add an automated runtime test for the status endpoint and counters.
2. Move shared-state JSON buffer allocation outside the shared-memory mutex where practical, while retaining a bounded and consistent snapshot strategy.
3. Add explicit peer-set semantics, beginning with a compatibility-safe `peer_first_seen` representation.
4. Add collector queue-saturation and disk-failure tests.
5. Benchmark status generation and steady-state request overhead.
6. Expand CI to current supported stable/mainline NGINX versions after validating the exact compatibility matrix.
7. Add packaging/service examples for the C collector.

## Dependencies and licensing

No new runtime dependency is introduced.

- NGINX — 2-clause BSD-style license; host/module API; actively maintained. Dynamic-module compatibility must be validated against each supported NGINX build.
- OpenSSL — Apache-2.0; TLS/X.509 inspection; actively maintained. Keep patched with the host NGINX/OpenSSL stack.
- ISO C/POSIX Unix-domain socket and file APIs — operating-system interfaces, not bundled third-party libraries.
- GCC or Clang — build tooling only; actively maintained.

The project remains Apache-2.0. Before a public production release, perform manual security, compatibility, licensing and source-similarity review.
