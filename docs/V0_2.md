# v0.2 — Operational visibility and hardening

v0.2 evolves the upstream identity monitor from a validated observable component into something an operator can run continuously and inspect safely.

The release remains observation-only. It does not block upstream connections or enforce certificate/SPKI policy.

## Planned v0.2 scope

1. Read-only NGINX status endpoint backed by the existing shared-memory identity state.
2. First-class NGINX directive for the structured-history Unix socket.
3. Export and state counters so dropped events are visible.
4. Explicit peer-first-seen semantics and peer-set visibility.
5. Productionized C history collector.
6. Broader NGINX compatibility CI.
7. Expanded correctness, failure and load tests.
8. Operator/security documentation.

The implementation stays in C. No JSON library, database client, Kafka client, systemd library, Python runtime collector, or other new runtime library dependency is introduced.

## Slice 1 — C collector hardening

The first v0.2 slice hardens `lab/history_collector.c` while keeping the v0.1 event transport compatible.

### Sync policy

The collector now accepts:

```bash
nginx-upstream-identity-history-collector \
  --sync always \
  /run/nginx/upstream-identity/history.sock \
  /var/log/nginx/upstream-identity.jsonl
```

or:

```bash
nginx-upstream-identity-history-collector \
  --sync none \
  /run/nginx/upstream-identity/history.sock \
  /var/log/nginx/upstream-identity.jsonl
```

`always` is the default and calls `fdatasync()` after every accepted event. This gives the strongest local durability semantics at the cost of one extra sync operation per identity-change event.

`none` relies on normal kernel/filesystem writeback. It reduces persistence overhead but an event acknowledged by the collector may still be lost after a sudden host or kernel failure.

Identity changes are expected to be rare, so `always` remains the conservative default.

### SIGHUP log reopen

The collector handles `SIGHUP` by reopening the configured history path.

This supports normal external log rotation:

```text
collector writing upstream-identity.jsonl
        |
        v
logrotate renames current file
        |
        v
new empty upstream-identity.jsonl created
        |
        v
SIGHUP collector
        |
        v
collector reopens configured path
```

The Unix datagram listener remains alive while the history file is reopened.

### Safer socket handling

Before binding, the collector checks an existing socket path with `lstat()`.

- no existing path: continue;
- existing Unix socket: unlink it and bind a fresh listener;
- existing regular file, directory or symlink: refuse to replace it.

After bind, the socket path is explicitly set to mode `0600`.

This reduces the risk of accidentally deleting an unrelated filesystem object and limits event injection to users that can access the socket according to filesystem permissions.

This does not make JSONL tamper-proof or audit-grade. Local users with sufficient filesystem privileges can still modify the history file or interfere with the collector.

### Runtime counters

On shutdown the collector reports process-local totals:

```text
received=<n> written=<n> dropped=<n> reopens=<n>
```

These counters are currently collector diagnostics only. A later v0.2 slice will add NGINX-side generated/sent/dropped/error counters to the shared status view.

## Compatibility

The positional v0.1 invocation remains valid:

```bash
nginx-upstream-identity-history-collector \
  /tmp/history.sock \
  /tmp/history.jsonl
```

It is equivalent to:

```bash
nginx-upstream-identity-history-collector \
  --sync always \
  /tmp/history.sock \
  /tmp/history.jsonl
```

The event schema remains v1 in this slice. Schema changes and the `peer_first_seen` naming transition are intentionally deferred until the status/state API is introduced, so collector hardening does not break existing v0.1 producers or tests.

## CI coverage added in this slice

CI now verifies:

- collector and sender compile as C11 with `-Wall -Wextra -Wpedantic -Werror`;
- Unix datagram transport still persists a valid event;
- collector socket permissions are `0600`;
- `--sync none` works;
- `--sync always` works;
- `SIGHUP` reopens a rotated history file;
- post-rotation events are written to the new file;
- the NGINX dynamic module still builds.

## Next implementation slice

The next substantial v0.2 slice should add the read-only status endpoint:

```nginx
location = /upstream-identity-status {
    upstream_identity_status;
}
```

The endpoint should expose a bounded JSON snapshot of shared state, including:

```text
upstream
peer
first_seen
last_seen
observations
changes
current certificate SHA-256
current SPKI SHA-256
```

and shared operational counters such as:

```text
peers_tracked
events_generated
events_exported
events_dropped
export_errors
identity_changes
```

The endpoint must be opt-in. Documentation should strongly recommend restricting it with normal NGINX access controls because it reveals internal upstream topology and certificate identities.

## Dependencies and licensing

No new runtime dependency is added in this slice.

- NGINX — 2-clause BSD-style license; host/module API; actively maintained. Dynamic-module compatibility must be validated against each supported NGINX build.
- OpenSSL — Apache-2.0; TLS/X.509 inspection; actively maintained. Keep patched with the host NGINX/OpenSSL stack.
- ISO C/POSIX Unix-domain socket and file APIs — operating-system interfaces, not bundled third-party libraries.
- GCC or Clang — build tooling only; actively maintained.

The project remains Apache-2.0. Before a public production release, perform manual security, compatibility, licensing and source-similarity review.
