# v0.1 — Observable upstream identity monitor

This branch turns the validated PoC into the first usable module slice while keeping the runtime implementation in C.

## Scope

v0.1 provides:

- observation of the actual selected upstream peer;
- live TLS leaf certificate SHA-256 and SPKI SHA-256;
- shared worker state keyed by upstream and peer;
- change classification: `first_seen`, `certificate_changed_same_key`, `public_key_changed`;
- state preserved across NGINX configuration reloads when the shared-memory zone is preserved;
- optional structured event export over a nonblocking Unix datagram socket;
- a small C collector that appends accepted events to JSONL and calls `fdatasync()` after each event.

The previously explored Python log-to-JSONL collector remains a separate PoC branch and is not part of this implementation.

## Architecture

```text
client
  |
  v
NGINX worker
  |
  +-- upstream peer lifecycle wrapper
  |      |
  |      +-- actual peer address
  |      +-- live TLS certificate / SPKI
  |
  +-- shared-memory longitudinal state
  |      |
  |      +-- classify identity change
  |      +-- ordinary NGINX change log
  |
  +-- structured event (change only)
         |
         +-- one nonblocking AF_UNIX/SOCK_DGRAM sendto()
                |
                v
          C history collector
                |
                +-- append JSONL
                +-- fdatasync
```

The request path never opens a history file, calls SQLite, waits for the collector, or retries delivery. If the collector is absent, its socket queue is full, or export otherwise fails, proxy traffic continues. Delivery is best-effort in v0.1.

## Configuration

Inside `http {}`:

```nginx
upstream_identity_state_zone upstream_identity_state 1m;
upstream_identity_history_socket /tmp/nginx-upstream-identity-history.sock;

upstream backend_tls {
    server 127.0.0.1:9443;
    keepalive 16;
    upstream_identity_peer_monitor;
}
```

`upstream_identity_history_socket` is optional. If omitted, the module keeps the existing logging and shared-state behavior without opening an export socket.

## Event schema

Each datagram is one JSON object, for example:

```json
{"schema_version":1,"timestamp":1786720000,"change":"public_key_changed","upstream":"backend_tls","peer":"127.0.0.1:9443","previous_cert_sha256":"...","current_cert_sha256":"...","previous_spki_sha256":"...","current_spki_sha256":"..."}
```

`first_seen` has empty previous hashes.

Schema version `1` is intentionally small and append-only. New fields can be added in later versions without changing the meaning of existing fields.

## Build the C collector

```bash
cc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 \
  lab/history_collector.c \
  -o /tmp/nginx-upstream-identity-history-collector
```

Run it before starting or exercising NGINX:

```bash
mkdir -p "$HOME/nginx-upstream-identity-poc/history"

/tmp/nginx-upstream-identity-history-collector \
  /tmp/nginx-upstream-identity-history.sock \
  "$HOME/nginx-upstream-identity-poc/history/upstream-identity.jsonl"
```

The collector creates the Unix datagram socket with a restrictive umask and opens the history file mode `0600` when newly created.

## Failure semantics

- collector not running: event send fails immediately; request processing continues;
- collector queue full: nonblocking send drops the event; request processing continues;
- collector or history write fails: collector exits; NGINX continues;
- NGINX full restart: shared-memory baseline resets, durable JSONL remains;
- NGINX reload: shared-memory baseline is expected to remain when the same zone is reused.

v0.1 does not guarantee delivery. That is deliberate: proxy availability is more important than history completeness in the NGINX worker path.

## Validation target

Before merging v0.1 to `main`, validate:

1. `first_seen` produces exactly one JSONL record.
2. Stable identity produces no new record.
3. Same-key certificate rotation produces exactly one `certificate_changed_same_key` record.
4. New key produces exactly one `public_key_changed` record.
5. Four workers concurrently observe a transition but only one change event is exported.
6. Configuration reload preserves the baseline and emits no new `first_seen`.
7. Full stop/start preserves JSONL history and produces a new `first_seen` for the new runtime baseline.
8. Collector absent does not change successful proxy responses.
9. Collector killed while NGINX is active does not crash or block workers.
10. High-load stable traffic shows bounded overhead relative to the same module with export disabled.

## Dependencies and licensing

No new runtime library dependency is introduced.

- NGINX: 2-clause BSD; host/module API; actively maintained. Compatibility with each target NGINX release must be tested because dynamic modules must match the NGINX build/ABI expectations.
- OpenSSL: Apache-2.0; TLS/X.509 inspection; actively maintained. The module already uses it through NGINX/OpenSSL APIs.
- ISO C/POSIX/Linux Unix-domain socket APIs: system interfaces, not a bundled third-party dependency.
- GCC or Clang: build tooling only; actively maintained. Compiler licensing does not impose copyleft on this module's output in normal use.

The project remains Apache-2.0. Before a public production release, perform manual security, compatibility, licensing, and source-similarity review.
