# Lab setup

This procedure is intentionally small. It proves only that a stock, unpatched NGINX build can load the PoC as a dynamic module and observe the TLS identity of an HTTPS upstream.

The instructions assume Ubuntu or Ubuntu on WSL.

## 1. Install build dependencies

```bash
sudo apt update
sudo apt install -y \
  build-essential \
  curl \
  ca-certificates \
  libpcre2-dev \
  zlib1g-dev \
  libssl-dev \
  openssl
```

The PoC uses the system OpenSSL development headers. No third-party C library is required by the module.

## 2. Clone this repository

```bash
cd ~/source
git clone https://github.com/zelinsky-alexander/nginx-extension-poc.git
cd nginx-extension-poc
```

Set a convenience variable:

```bash
export POC_DIR="$PWD"
```

## 3. Download an official NGINX source release

For the first PoC, build a private local NGINX instead of trying to match Ubuntu's packaged NGINX build flags. This still tests an unpatched stock NGINX source tree and a separately built dynamic module.

Choose the NGINX version you want to test. Example:

```bash
export NGINX_VERSION=1.28.0
cd /tmp
curl -fLO "https://nginx.org/download/nginx-${NGINX_VERSION}.tar.gz"
tar xzf "nginx-${NGINX_VERSION}.tar.gz"
cd "nginx-${NGINX_VERSION}"
```

If you use a different current stable release, change only `NGINX_VERSION`.

## 4. Configure NGINX with the PoC as a dynamic module

Create an isolated install prefix:

```bash
export NGINX_PREFIX="$HOME/nginx-upstream-identity-poc"
```

Configure:

```bash
./configure \
  --prefix="$NGINX_PREFIX" \
  --with-http_ssl_module \
  --with-compat \
  --add-dynamic-module="$POC_DIR"
```

Build and install:

```bash
make -j"$(nproc)"
make install
```

Confirm the module exists:

```bash
ls -l "$NGINX_PREFIX/modules/ngx_http_upstream_identity_module.so"
```

Expected: the `.so` file exists.

## 5. Install the lab NGINX configuration

```bash
cp "$POC_DIR/lab/nginx.conf" "$NGINX_PREFIX/conf/nginx.conf"
```

Validate configuration:

```bash
"$NGINX_PREFIX/sbin/nginx" -t -p "$NGINX_PREFIX/"
```

Expected:

```text
syntax is ok
test is successful
```

## 6. Generate two test backend identities

```bash
cd "$POC_DIR"
bash scripts/generate-test-certs.sh
```

This creates:

```text
lab/certs/backend-a.cert.pem
lab/certs/backend-a.key.pem
lab/certs/backend-b.cert.pem
lab/certs/backend-b.key.pem
```

Both certificates use the DNS SAN `backend.test`, but they have different keys and therefore different certificate and SPKI fingerprints.

## 7. Start backend A

Open terminal 1:

```bash
cd "$POC_DIR"
openssl s_server \
  -accept 127.0.0.1:9443 \
  -cert lab/certs/backend-a.cert.pem \
  -key lab/certs/backend-a.key.pem \
  -www
```

Leave it running.

## 8. Start the PoC NGINX

Open terminal 2:

```bash
export NGINX_PREFIX="$HOME/nginx-upstream-identity-poc"
"$NGINX_PREFIX/sbin/nginx" -p "$NGINX_PREFIX/"
```

Follow the error log:

```bash
tail -F "$NGINX_PREFIX/logs/error.log"
```

## 9. Send the first request

Open terminal 3:

```bash
curl -v http://127.0.0.1:8080/
```

The response body is generated by `openssl s_server -www`.

In terminal 2, look for a log entry beginning with:

```text
upstream_identity
```

A successful observation should resemble:

```text
upstream_identity peer="127.0.0.1:9443" tls="TLSv1.3" alpn="" cert_sha256="..." spki_sha256="..." issuer="..." san_dns="backend.test"
```

The exact TLS version can differ depending on the OpenSSL versions and configuration. An empty ALPN value is acceptable for this first `openssl s_server` lab because no ALPN protocol is explicitly negotiated.

## 10. Stop the lab

Stop NGINX cleanly:

```bash
"$NGINX_PREFIX/sbin/nginx" -p "$NGINX_PREFIX/" -s quit
```

Stop `openssl s_server` with `Ctrl+C`.

## Troubleshooting

### `unknown directive "upstream_identity_monitor"`

The module was not loaded. Check:

```bash
ls -l "$NGINX_PREFIX/modules/ngx_http_upstream_identity_module.so"
head -n 3 "$NGINX_PREFIX/conf/nginx.conf"
```

The first directive should be:

```nginx
load_module modules/ngx_http_upstream_identity_module.so;
```

### NGINX starts but logs `peer_connection_missing`

This is an important PoC result rather than merely a setup error. It means the header-filter hook does not retain the upstream connection in the tested NGINX request path. Record the NGINX version and test result; the next experiment should move observation closer to the upstream connection lifecycle rather than adding storage or other features.

### NGINX logs `reason=not_tls`

Check that the `proxy_pass` URL is `https://backend_tls`, not `http://backend_tls`.

### `connect() failed (111: Connection refused)`

Confirm the backend is listening:

```bash
ss -ltnp | grep 9443
```

### Port 8080 is already in use

Find the owner:

```bash
ss -ltnp | grep 8080
```

Either stop the conflicting process or temporarily change `listen 8080;` in the lab configuration.

## Why build a local NGINX first?

Ubuntu's packaged NGINX may have a distribution-specific module ABI/configuration signature. Matching that exactly adds packaging complexity that does not answer the first feasibility question.

This lab first proves:

```text
official unmodified NGINX source
        +
external dynamic module
        +
HTTPS upstream
        =
observable upstream TLS identity
```

If this succeeds, a later packaging test can target Ubuntu's system NGINX specifically.
